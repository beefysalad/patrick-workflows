# Phase 1a spike results (2026-10-03)

Probes: a temporary `spike-probe` agent (tools Read, Skill; model sonnet) and `spike-probe` skill, loaded with `claude -p --plugin-dir <repo>`. Both were removed after the spike.

## Dev loop
`claude --plugin-dir <path>` loads a plugin from a directory for one session. Use it for development and for the smoke test; no marketplace install or version bump is needed to try changes.

## S1: model per dispatch
- Agent frontmatter `model: sonnet` is the default: the probe reported `MODEL: claude-sonnet-5-5` with no override.
- A per-dispatch override works: dispatched with model `opus`, it reported `MODEL: claude-opus-5-5`.
- Consequence: `final-reviewer` keeps `model: sonnet` in frontmatter; the skill passes `opus` per dispatch for the impact and security critics and the lite combined critic.

## S2: reading the workspace under ~/.claude/tickets
- Without a rule, a subagent's Read of `~/.claude/tickets/...` is denied (path is outside the working directory).
- With `Read(~/.claude/tickets/**)` allowed, the read succeeds (`READ: spike-ok`).
- Consequence: the README recommends these allow rules:
  - `Read(~/.claude/tickets/**)`
  - `Write(~/.claude/tickets/**)` and `Edit(~/.claude/tickets/**)` (fixer reports, orchestrator files)
  - `Bash(bash *skills/review-mine/scripts/*)` for the review scripts
  - the project's own gate commands

## S3: plugin-agent frontmatter limits (hooks, permissionMode, mcpServers)
Not verified in this spike. Nothing in Phase 1a depends on these fields; recheck before any later phase relies on them.

## S4: skill base directory
The skill reported `BASE: <repo>/skills/spike-probe` and ran `bash "<base>/../../scripts/validate.sh"` successfully. Consequence: scripts live in `skills/review-mine/scripts/` and are called as `bash "$SKILL_DIR/scripts/<name>.sh"`.

## S5: agents can load skills
The probe agent (tools include Skill) loaded `superpowers:test-driven-development`. Consequence: `ticket-fixer` loads the TDD skill itself.

## S6: agent naming
Plugin agents are dispatched as `patrick-workflows:<agent-name>` (e.g. `patrick-workflows:final-reviewer`).
