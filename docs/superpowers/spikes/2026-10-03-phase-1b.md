# Phase 1b spike results (2026-10-03)

Probe: a temporary `spike-probe` agent (Read, Write, Grep, Glob, Skill, Bash; sonnet), run with `claude -p --plugin-dir <repo>`; removed afterwards.

## S7: can a subagent dispatch subagents?
No. The probe reported it has no dispatch tool ("My available tools are Read, Write, Skill, and Bash"). Consequence: the main session is the only orchestrator; BUILD's task driver and the review loop run in the main session.

## S8: writing-plans overrides inside an agent
- With an allow rule written as `Edit(/private/tmp/...)` (single leading slash) the save was **denied**; with `Edit(//private/tmp/...)` it succeeded. Absolute paths in permission rules need a double leading slash; `~/...` rules work as written.
- The overrides were honored: plan saved to the given path, nothing committed, no execution-approach question.
- Side effect: the agent also wrote "No commits are to be made as part of this plan" into the plan's constraints, applying "do not commit" to the tasks themselves. Consequence: `ticket-planner` must say the no-commit rule applies only while writing the plan; the plan's tasks keep their normal commit steps.

## S9: working in a worktree outside the starting directory
`git worktree add ../x` then writing into it from the session was refused (Write and `git -C ../x status` both needed approval). Claude Code's own `EnterWorktree` tool creates the worktree under `.claude/worktrees/` inside the repo and switches the session into it; `EnterWorktree` with `path` re-enters an existing one. Consequence: PLAN uses `EnterWorktree` when the user explicitly picks a worktree, renames the created branch to the ticket branch, and records the path; the router re-enters it with `EnterWorktree(path)` on resume. Main checkout stays the default.
